# 判定ランプ (JudgeLamp)

ゲーム画面の上に小さなランプを重ねて表示する Android アプリです。
画面に GREAT・GOOD・MISS の文字が出た瞬間に、ランプの色が変わります。
新しい判定が出るたびに色は上書きされ、ランプをタップすると緑に戻ります。

- 緑:最後にタップしてから、対象の判定はまだ出ていない
- 青:GREAT / GOOD(早く叩いた)
- 赤:GREAT / GOOD(遅く叩いた)
- 黄:MISS

ゲーム本体には一切触れません。Android 標準の画面キャプチャで、判定の文字が出る場所だけを見ています。

## APK の作り方

このフォルダは Android Studio のプロジェクトです。APK(インストール用ファイル)にするには、次のどちらかが必要です。

### A. GitHub に置いて自動ビルド(パソコン不要)

1. GitHub にリポジトリを作り、このフォルダの中身をそのまま `main` ブランチに入れます。
2. 自動でビルドが走ります(`.github/workflows/build.yml`)。数分かかります。
3. リポジトリの「Releases」に `JudgeLamp.apk` が出るので、スマートフォンのブラウザでダウンロードします。

### B. Android Studio でビルド(パソコン)

1. Android Studio でこのフォルダを開きます。
2. スマートフォンを USB でつないで ▶(Run)を押すか、メニューの Build > Build APK(s) で APK を作ります。

## インストール後の最初の設定

「ランプを表示する」を押すと、順番に許可を求められます。

1. **他のアプリの上に重ねて表示**:設定画面が開くので「判定ランプ」を選んでオンにします。
   - スイッチが灰色で押せない場合(Android 15 以降でよく起きます):
     設定 > アプリ > 判定ランプ > 右上の「︙」 > 「制限付き設定を許可」を押してから、もう一度試してください。
2. **通知**:動作中の通知に「緑に戻す」「終了」ボタンが付きます。許可しなくてもランプは動きます。
3. **画面の録画/キャスト**:「開始」を押します。これは毎回必要です。

## 使い方

1. 「ランプを表示する」を押して、ゲームを開きます。ランプは画面上端の、中央より少し右に出ます。
2. 曲を始める前にランプをタップして緑にします。
3. 対象の判定が出ると赤になります。
4. ランプはドラッグで動かせます(横向き・縦向きで別々に位置を覚えます)。
5. 終わるときは、アプリの「ランプを終了する」か、通知の「終了」を押します。

設定できるもの:赤にする判定(GREAT / GOOD / MISS)、ランプの大きさ、感度。

## 知っておいてほしいこと

- **実機ではまだ動かしていません。** 検出の部分は下のとおり確認済みですが、アプリ全体は
  ビルドも実機での動作確認もできていない状態でお渡ししています。
- **GOOD は 1 枚のスクリーンショットだけで合わせてあります。** GREAT と MISS はプレイ動画で
  確認できましたが、GOOD が出る動画は手元にないため、実際のプレイ中に拾えるかは未確認です。
- **画面に出なかった判定は拾えません。** 同時押しなどで、文字が同じ瞬間に PERFECT で上書きされて
  一度も表示されなかった場合は、赤になりません。見本の動画でも、リザルトの MISS 3 回に対して、
  画面に MISS と出たのは 2 回でした。
- **1 台の画面に合わせてあります。** 文字の位置と大きさは、見本の動画(2424×1080 の画面)に合わせています。
  画面の比率が違う機種や、ゲームの表示設定を変えた場合は、反応しないことがあります。
- ランプを画面中央の判定の文字に重ねると、文字が隠れて検出できなくなります。
- ランプのある場所(約 4〜5 mm 四方)はタップがランプに吸われます。ノーツを叩く場所には置かないでください。
- 画面をロックしたり、システム側で画面の共有を止めたりすると、ランプは自動で消えます
  (見張っていないのに緑のまま残ることはありません)。

## 早い・遅いの見分け方

ゲーム画面には早い・遅いの表示がないため、ノートの位置から判断しています(`TimingProbe.java`)。
遅く叩いたノートは判定線を通り過ぎてから消え、早く叩いたノートは線に届く前に消えます。
そこで GREAT / GOOD の文字が出た瞬間に、3 本の判定線の「向こう側」からノートの色が消えたかを見て、
消えていれば「遅い」、そうでなければ「早い」とします。

- 早めに寄せた録画:GREAT / GOOD 33 回すべてを「早い」と判定
- 遅めに寄せた録画:29 回のうち 26 回を「遅い」、3 回を「早い」と判定
  (この 3 回が本当に早かったのか、見分けそこねたのかは録画からはわかりません)
- 同時押しで別のノートが線の向こうで消えた場合や、エフェクトでノートが隠れた場合は、逆に出ることがあります。
- 文字が出てから 0.1 秒以内に続けて出た同じ判定は、1 回として扱います。

## しくみと確認結果

- 画面を横向き・高さ 540 px に縮めて取り込み、判定の文字が出る小さな範囲だけを毎フレーム調べます。
- 見本の画像(`app/src/main/assets/great.tpl`, `good.tpl`, `miss.tpl`)と形を比べます。背景の色や
  エフェクトの影響を減らすため、明るさのなだらかな変化を取り除いてから比べています(`JudgeDetector.java`)。
- 見本のプレイ動画(約 3 分、11,194 フレーム)にアプリと同じ検出コードをかけた結果:
  - 画面に出た GREAT 3 回・MISS 2 回をすべて検出、誤検出は 0 回(GOOD の誤反応も 0 回)
  - エフェクトにほぼ隠れていた 1:40 の GREAT も「標準」感度で検出(「低」では拾いません)
  - 取り込みが 1 フレームおきに落ちた場合、縮小方法を変えた場合、半ピクセルずれた場合でも同じ結果
  - 文字なしのフレームの一致度は最大 0.31(語全体)/ 0.42(語の半分)。
    反応のしきい値は 1 フレームなら 0.50 / 0.70、2 フレーム連続なら 0.45 / 0.60
- GOOD について:
  - 見本はスクリーンショットの表示画面(ゲーム部分が横 1080 px に縮小されたもの)から作りました。
    画面上部のバーやロゴの位置を動画と重ね合わせて、文字の位置を割り出しています。
  - そのスクリーンショットをアプリの検出コードにかけると GOOD として検出されます。
  - 同じ「縮小してから戻す」手順で GREAT と MISS の見本を作り直しても、動画の実物との一致度は
    0.01 ほど下がるだけで、検出結果は変わりませんでした。縮小による劣化の影響は小さいと見ています。
- 同じ確認をやり直すには:

  ```sh
  javac -d out app/src/main/java/app/judgelamp/JudgeDetector.java tools/DetectorHarness.java
  ffmpeg -i play.mp4 -vf scale=1212:540:flags=area -pix_fmt rgba -f rawvideo - \
    | java -cp out DetectorHarness 1212 540 60 app/src/main/assets scores.txt
  ```

## 見本の画像を作り直す

`tools/make_templates.py` が、高さ 540 px に縮めたスクリーンショット 3 枚(GREAT・GOOD・MISS)から
見本を切り出します。別の機種に合わせる場合は、このスクリプトの切り出し位置を変えてください。

## 署名キーについて

`keystore/judgelamp.keystore` は、どこでビルドしても同じ署名になるようにプロジェクトに入れてある
公開のキーです(上書きインストールができるようにするため)。個人で使うぶんには問題ありませんが、
ストアで配布する場合は自分のキーに差し替えてください。
